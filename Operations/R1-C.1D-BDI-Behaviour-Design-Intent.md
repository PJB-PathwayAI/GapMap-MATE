## Purpose

To define the minimum changes required to bring the deployed smudgeOrchestrator's generation layer into alignment with the approved Companion Behaviour Refinement v1.0 (CBR) and Cipher's cross-phase voice consistency constraint.

**In scope:** smudgeOrchestrator generation layer only (the `buildGenerationPrompt` function and the context passed to it).

**Out of scope (per directive):** Architecture, companionCore, engines, lifecycle contracts, persistence, extraction layer.

---

## Root Cause Analysis

The traceability review (R1-C.1D-BR) established that OBS-001 is an implementation gap, not a doctrinal gap. Inspection of the deployed code reveals the specific mechanism:

### What companionCore Already Does

companionCore v1.1.0 already generates `behavioural_notes` in its `generateFlowGuidance()` function. These notes include:

| CBR Area | companionCore behavioural_note | CBR Section |
|---|---|---|
| Topic completion | `"CHECKPOINT: 'X' just reached substance. Consider a topic completion checkpoint: 'I think I've got a good picture of that now. Anything else before we move on?' Don't keep probing this area."` | CBR §2 |
| Natural discovery | `"Suggested next area: 'X'. This is a suggestion, not a script — if the user naturally covers another area, move with them."` | CBR §6 |
| Pacing / wrap-up | `"If the user signals they want to wrap up or move on, respect that. You can reflect what you have and ask if they want to continue or pause."` | CBR §3/§6 |
| Low confidence flag | `"LOW CONFIDENCE FLAG: User self-reported confidence is below 4/10. Be extra careful not to push."` | EB Ch.2 Psychological Safety |
| CONFIRMING guidance | `"The operational picture has been presented. Await the user's explicit confirmation before proceeding."` | CBR §1 / EB Ch.2 |
| CONFIRMED guidance | `"Picture confirmed. The user has agreed this is them. Phase Three (Evaluate) can begin when ready."` | CBR §1 |

### What smudgeOrchestrator Does NOT Do

The smudgeOrchestrator's `buildGenerationPrompt` function:
1. Does NOT read `companionResult.guidance.behavioural_notes` — the notes are generated but never consumed
2. Does NOT pass `companionResult.session.mode` (current phase) to the generation context
3. Does NOT include CBR §4 voice characteristics in the system prompt
4. Does NOT include CBR §1 reflection pacing instructions
5. Does NOT include CBR §3 conversational momentum instructions
6. Does NOT include CBR §6 natural discovery instructions
7. Does NOT include cross-phase voice consistency constraint

### Summary

companionCore is generating the right signals. The generation layer is not consuming them and does not have the CBR-mapped instructions to act on them. This is why the deployed Smudge exhibits the behaviours described in OBS-001.

## Design Intent

### Change 1: Pass behavioural_notes to generation context

**File:** `functions/smudgeOrchestrator.ts` — context construction (not `buildGenerationPrompt` itself)

**What:** Add `behavioural_notes` from `companionResult.guidance.behavioural_notes` to the generation context object (`ctx`).

**How:** Read the existing field from companionCore's output (no companionCore change):
```typescript
behavioural_notes: companionResult.guidance?.behavioural_notes || []
```

**Why:** The notes are already generated by companionCore. They contain checkpoint signals, natural discovery guidance, and pacing notes that the generation layer needs to produce CBR-aligned behaviour.

**What does NOT change:** companionCore, its guidance generation, or its output structure.

---

### Change 2: Pass current phase to generation context

**File:** `functions/smudgeOrchestrator.ts` — context construction

**What:** Add `current_phase` from `companionResult.session.mode` to the generation context.

**How:** Read the existing field (no companionCore change):
```typescript
current_phase: companionResult.session.mode
```

**Why:** The cross-phase voice consistency constraint requires the LLM to know which phase the user is in so it can adapt conversational purpose while maintaining persistent identity.

**What does NOT change:** companionCore, session structure, or lifecycle logic.

---

### Change 3: Rewrite generation system prompt

**File:** `functions/smudgeOrchestrator.ts` — `buildGenerationPrompt` function, system line only

**Current:**
```
You are Smudge, a companion for people leaving the military. You are warm, practical, and unhurried. You are having a conversation, not conducting an interview.
```

**Proposed:**
```
You are Smudge, a companion for people leaving the military. You are the same person in every conversation — warm, practical, unhurried — but how you help changes depending on where the person is in their journey. Right now they are in the {current_phase} phase. Adapt what you focus on to match, but never change who you are.

You are having a conversation, not conducting an interview. You speak like a person, not a model — short sentences, everyday words, start with the point not the setup. No corporate language, no therapy-speak, no "what I'm hearing from you is." If a word wouldn't come out of someone's mouth in a pub, don't use it here.
```

**Maps to:**
- CBR §4: Voice characteristics (sentence length, vocabulary, anti-patterns)
- Cipher's constraint: Cross-phase voice consistency ("same person in every conversation... adapt what you focus on... never change who you are")

**What does NOT change:** The response rules (rules 1-10 remain intact, with additions below).

---

### Change 4: Add CBR-mapped generation rules

**File:** `functions/smudgeOrchestrator.ts` — `buildGenerationPrompt` function, rules section

**What:** Add the following rules after the existing 10 rules:

**Rule 11 — Reflection pacing (CBR §1):**
```
11. Use mini acknowledgements between answers — "Got you", "Makes sense", "Right" — not full reflections. Save reflections for milestones: a significant personal disclosure, connecting two themes the user hasn't linked, or before transitioning to a new area. Do not reflect after every answer.
```

**Rule 12 — Topic completion (CBR §2):**
```
12. If the guidance notes say an area has reached substance, move toward closure. Use a checkpoint like "I think I've got a good picture of that now — anything else before we move on?" Do not keep probing the same area. If the user signals boredom or frustration, close the topic immediately.
```

**Rule 13 — Conversational momentum (CBR §3):**
```
13. Let questions chain naturally — two or three on a related thread before any reflection. Vary the rhythm. Not every exchange is the same shape. If the user is on a roll, follow it rather than redirecting.
```

**Rule 14 — Natural discovery (CBR §6):**
```
14. Be curious, not a checklist. If the user naturally covers something you hadn't planned to ask, follow it. The suggested next area is a suggestion, not a script. Understanding is measured by quality, not quantity.
```

**Why:** Each rule maps directly to an approved CBR section. No new doctrine. No new behaviour. These are the instructions the LLM needs to exhibit behaviour that companionCore already signals for.

**What does NOT change:** Rules 1-10 (existing rules remain intact and take precedence).

---

### Change 5: Include behavioural_notes in generation context

**File:** `functions/smudgeOrchestrator.ts` — `buildGenerationPrompt` function, context section

**What:** Add the behavioural_notes to the prompt context block:

```
- Behavioural guidance from the system: {behavioural_notes joined, or "none" if empty}
```

**Why:** The LLM needs the checkpoint signals, natural discovery guidance, and pacing notes to act on rules 12 and 14. Without these notes, the LLM cannot know when an area has reached substance or what the suggested next area is.

**What does NOT change:** The notes themselves (generated by companionCore, unchanged).

---

### Change 6: Add military authenticity to generation (CBR §5)

**File:** `functions/smudgeOrchestrator.ts` — `buildGenerationPrompt` function, rules section

**What:** Add:
```
15. Use the user's own language. If they say "shell scrape," say "shell scrape." If they say "SOPs," say "SOPs." Do not sanitise or upgrade their language to corporate terminology during discovery. Translation happens later, not here.
```

**Why:** CBR §5 was validated in Exercise LENS 2 and is part of the approved specification. The current prompt's rule 10 ("Do not pretend to have military experience") is about authenticity of identity, not about language matching. This is a distinct behavioural requirement.

**What does NOT change:** The extraction prompt or any engine logic.

## Verification Plan (Post-Implementation)

After implementation, the following tests would verify alignment:

| Test | CBR Area | Expected Behaviour |
|---|---|---|
| Send 3 short factual answers on same topic | §2 Topic Completion | Smudge uses checkpoint pattern after 2nd or 3rd answer, moves to next area |
| Send a rich, detailed answer | §2/§6 | Smudge does not probe further on that area — quality sufficient |
| Observe 5 consecutive turns | §1 Reflection Pacing | Max 1-2 full reflections, rest are mini acknowledgements |
| Observe response language | §4 Voice | No "what I'm hearing is", no therapy-speak, varied sentence length |
| User uses military slang | §5 Military Authenticity | Smudge mirrors the user's language, does not upgrade to corporate |
| User volunteers unplanned info | §6 Natural Discovery | Smudge follows the user's lead, does not redirect to suggested area |
| Check phase adaptation | Cross-phase | Voice is consistent, focus adapts to current phase |

**No automated regression suite change required.** The existing 7 regression tests verify lifecycle, persistence, and ownership — none of which are affected by generation layer changes. The verification above is behavioural observation, consistent with the PROOF methodology (Exercise, AAR).

## Risk Assessment

| Risk | Likelihood | Mitigation |
|---|---|---|
| LLM ignores new rules | Medium | Rules are specific and explicit. Behavioural notes provide concrete signals. Exercise validation required. |
| behavioural_notes are empty | Low | companionCore always generates notes. Fallback to "none" if empty. |
| Voice changes feel jarring | Medium | Read-aloud test (CBR §4) required during exercise validation. |
| Phase context causes LLM to announce phases | Low | Rule 2 (existing) already prohibits internal terminology. |
| Changes affect lifecycle behaviour | Very Low | No lifecycle, engine, or companionCore changes. Generation only. |
